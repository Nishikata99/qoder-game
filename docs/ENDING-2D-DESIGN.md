# Blood Ante · 结局 2D 像素过场设计（待确认）

> 范围：**胜利结局**与**死亡结局**各加一段 2D 像素过场。
> **胜利：现有 3D `endingB` 保留在前，播完再接 2D**（两段串联，共约 15.7s，不可跳过）。
> **死亡：新增 2D 过场**（7.0s，可跳过）。
> 全部 Canvas 2D 程序化绘制，零外部素材；`GameEngine.ts` 零改动。
> 沿用 `src/narrative/cutsceneScript.ts` 的三层视差 + 整数矩形范式。

---

## 0. 与现状的差异

| 项 | 现状 | 改后 |
|---|---|---|
| 胜利 | `beginNarrative('endingB')`：3D 机位 `table → endingReach`、缝线微光、伸手剪影、黑屏，7.2s → 结算屏 | **3D endingB（7.2s）→ 2D「赎契」（8.5s）→ 结算屏**；全程不可跳过 |
| 死亡 | 无演出，直接弹结算屏 | **2D「补针」（7.0s）→ 结算屏**；可 Space/Esc 跳过 |
| 触发 | `gameOver(winner='player')` 分支 | 同 + `winner='boss'` 分支 |
| `NarrativeMode` | `'endingB'` | 保留 `'endingB'`（3D 段），另加 2D 结局 spec |

3D 的 `endingReach` 机位、`reachHand`、`sutureGlow` 动作**继续使用**，作为胜利结局的前半段；2D 结局是它的续篇，不替代。

> **为什么串联不替换**：3D 段负责"近距离、看得清"的情绪爆发（缝线发光、伸手），2D 段负责"拉远、交代去向"的收束（走廊、灯、名单墙）。一段近一段远，层次互补；两段加起来约 15.7s，作为一次性通关终局可以接受。

## 1. 胜利结局 ·「赎契」（8.5s，接在 3D endingB 之后）

**叙事意图**：3D 段停在"缝线里透出微光、你伸手"的黑场。2D 段从这里接手：**黑场亮起，光已经在你手上**。你赢了，但"赢"只是把名字从名单上划掉、换成别人。走出那道门，走廊尽头还亮着一盏灯。

> 衔接：3D 段结尾是 `black:1`（全黑）+ 缝线声。2D 段第一帧也从全黑起、**无缝续上同一个音效余韵**，玩家读不出是两套系统。

### 分镜

| 时间 | 层 | 事件 | 音效 | 字幕 |
|---|---|---|---|---|

| 2.0–3.0 | 中景 | 缝账人的**残躯**瘫在桌沿，胸口缝线**透出暖光**（复用 ch3 刻痕色） | `stitch` | |
| 2.4 | — | | | ①「缝线里透出一点光——像有人把最后一口气缝了进去。」 |
| 3.0–4.2 | 前景 | **你的手**从画面右下伸入，指尖触到缝线；光顺着指尖爬上手腕 | `bossBreath` | |

**视觉要点**
- 调色：暗红/锈褐为主，**唯一的暖光源**是缝线与走廊尽头的灯（骨白偏黄），形成"死亡里唯一的暖"的对比
- 人影高度只有 30px（逻辑），刻意做小——不看清脸，只读"有人在等"
- 半张纸的撕边用 2px 锯齿，与游戏内契纸呼应

**关键帧**
1. `t=1.4` 牌桌残局（后拉中点）
2. `t=2.6` 缝线透光特写
3. `t=3.8` 手触缝线
4. `t=5.0` 缝线绽开成走廊
5. `t=6.4` 灯下人影抬手
6. `t=7.6` 灯灭

## 2. 死亡结局 ·「补针」（7.0s）

**叙事意图**：你输了，被缝进名单。不是惨死，而是**被归档**——像一件到期的抵押物。

| 0.5–1.6 | 背景 | 名单板特写：前面 8 道刻痕，最后一道**空槽**（已发光） | | |

**视觉要点**
- 与第 3 层过场（补针刑台）**视觉延续**，但更近、更冷：刻痕特写、手套的皮革质感、血从笔画边缘渗

4. `t=4.2` 刻痕扩散成轮廓

6. `t=6.3` 拉远成整面墙

## 3. 技术设计

### 3.1 接入点

```
gameOver(winner) 事件
  ├ winner === 'player' && phase === 'victory'
  │     → beginNarrative('endingB')               // 3D，既有，不可跳
  │     → onFinish 后 → beginEnding('endingWin')  // 2D 续篇，不可跳
  │     → 2D onFinish → 结算屏
  └ winner === 'boss' && phase === 'gameOver'
        → beginEnding('endingLose')               // 2D，可跳过
        → 结算屏
```

- 胜利的 2D 段**在 `NarrativeDirector` 的 `onFinish` 之后启动**，而不是并行：两段共用同一块覆盖区，避免叠加
- 死亡段独立启动，不需要 3D
- `EndingOverlay` 复用 `CutsceneOverlay` 的结构（canvas + 字幕 + 跳过），只是 `spec` 来自 `endingScript.ts`；结局不需要"恢复引擎"（引擎已终局）
- **结算屏 gate**：`finished && !narrativeActive` 保持原样即可——只要 2D 结局也计入 `narrativeActive`，结算屏就会自动被推后

### 3.2 文件

| 文件 | 状态 | 作用 |
|---|---|---|
| `src/narrative/endingScript.ts` | 新增 | 两段结局分镜 + 绘制函数（复用 `cutsceneScript` 的 `rect/glow/ease/span` 等工具，需把这些从内部导出） |
| `src/narrative/CutsceneOverlay.tsx` | 修改 | 加 `mode: 'transition' \| 'ending'`；`ending` 模式不调 `onResumeEngine`、按 spec 决定是否显示跳过按钮 |
| `src/App.tsx` | 修改 | 胜利：`endingB` 的 `onFinish` 链到 2D；`gameOver(winner='boss')` 起死亡 2D；两段都计入 `narrativeActive` |
| `src/narrative/cutsceneScript.ts` | 修改 | 导出绘制工具函数供结局复用 |
| `src/narrative/NarrativeDirector.ts` | 不改 | `endingB` 继续用（只是 `onFinish` 多了个续接回调） |
| `AGENTS.md` | 修改 | 补结局过场契约 |

### 3.3 时长与跳过

| 项 | 胜利（3D+2D） | 死亡（2D） |
|---|---|---|
| 时长 | 7.2s + 8.5s ≈ 15.7s | 7.0s |
| 跳过 | **不可跳过**（`endingB` 已不可跳，2D 段同样不显示跳过键、吞掉 Space/Esc） | **可跳过**：Space/Esc/点击跳过按钮，0.25s 淡出 |
| 结算屏 | 2D 结束 → 现有结算屏 | 同 |

- 胜利不 pause 引擎（已终局，无计时可暂停）
- 胜利段之所以长：**通关终局是一次性的**，值得给足情绪时间；且分两段（近→远）后单段并不拖沓
- 死亡段可跳过：失败是高频事件，重复玩家需要能快速重来

### 3.4 暂停 / 后台

- 结局期间 `togglePause` 不生效（已终局）；Esc 按赢/输分别处理（胜利吞掉，失败跳过）
- 切后台（`document.hidden`）时 2D rAF 自动停摆，回前台继续（复用 `Cutscene2D` 现有逻辑）
- **胜利段不可跳过**意味着玩家必须看完约 15.7s；切后台回来会从停摆处继续，不会丢失进度

### 3.5 e2e

- 现有 7 个用例不清层、不打终局，**不受影响**
- 为保险：结局过场同样受 `?skipcutscene=1` / `navigator.webdriver` 控制（不挂载，直接出结算屏）——**注意这会让 e2e 里"胜利不可跳过"的语义失效，只在测试环境如此**
- 本地验收加 `?cutscene=1` 强制播放（含结局）

## 5. 验收标准

1. 胜利：第 3 层 Boss 倒下 → **3D endingB 7.2s → 2D「赎契」8.5s** → 结算屏「血契已赎」；全程无跳过键，Space/Esc 无效
2. 死亡：玩家血袋见底 → **2D「补针」7.0s（可 Space/Esc 跳过）** → 结算屏「补针完成」
3. 胜利两段衔接处无跳帧：3D 的全黑帧与 2D 的首帧都是纯黑，音效连贯
4. 像素清晰、三层视差、暗调一致
5. 1280×720 / 1920×1080 / 手机竖屏正确 letterbox
6. `typecheck / 单测 / build / e2e` 全绿
7. 生产包无调试钩子
